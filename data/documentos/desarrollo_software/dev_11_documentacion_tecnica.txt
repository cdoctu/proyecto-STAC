Guía de documentación técnica

La documentación técnica ayuda a que cualquier persona del equipo entienda un sistema sin tener que preguntar al autor. Cada repositorio debe tener un archivo README con el propósito del proyecto, los pasos para instalarlo y el comando para correr las pruebas. Las decisiones importantes de arquitectura se registran en documentos cortos llamados ADR, que explican qué se decidió, por qué y qué alternativas se descartaron. Las APIs se documentan con el estándar OpenAPI para que la documentación se genere desde el código. Cuando un cambio modifica el comportamiento de un servicio, el pull request debe incluir la actualización de la documentación. Cada trimestre el líder técnico revisa que los documentos sigan vigentes y borra los que ya no sirven.
